# Project 03c — One tool, three languages

**Goal:** implement the same tiny CLI, `greet`, in Go, Rust and Python; package each with
its nixpkgs builder; give every package a `passthru.tests` version check and a behaviour
check; and add one test that proves the three implementations agree.

The CLI's contract:

| Command | Output |
|---|---|
| `greet` | `Hello, world!` |
| `greet NAME` | `Hello, NAME!` |
| `greet --version` | `greet 1.0.0` |

**You will practise:**

- **Language builders** — `buildGoModule`, `rustPlatform.buildRustPackage`,
  `python3Packages.buildPythonApplication`, each in `finalAttrs` form.
- **`package.nix` as a function of its dependencies** — three files, three different
  argument lists, one `callPackage`.
- **Tests travel with the package** — `testers.testVersion` and a `runCommand` behaviour
  test in each package's `passthru.tests`, using `finalAttrs.finalPackage`.
- **A contract test across packages** — a `runCommand` that diffs all three.

## The three implementations

### Go

```text file=go/go.mod
module example.com/greet

go 1.22
```

```go file=go/main.go
package main

import (
	"fmt"
	"os"
)

// Overridden at link time by the package: -X main.version=...
var version = "dev"

func greeting(args []string) string {
	if len(args) == 0 {
		return "Hello, world!"
	}
	return "Hello, " + args[0] + "!"
}

func main() {
	args := os.Args[1:]
	if len(args) == 1 && args[0] == "--version" {
		fmt.Println("greet", version)
		return
	}
	fmt.Println(greeting(args))
}
```

def main():
    args = sys.argv[1:]

## The three packages

Each has the same shape: builder, `finalAttrs`, structured attributes, the language's
dependency story, two tests, `meta`. The tests are written once per file because each
refers to *its own* `finalAttrs.finalPackage` — so they keep testing the package after
any override.

```nix file=greet-go.nix
{
  lib,
  buildGoModule,
  runCommand,
  testers,
}:

buildGoModule (finalAttrs: {
  pname = "greet-go";
  version = "1.0.0";
  src = ./go;

  __structuredAttrs = true;

  vendorHash = null;

  ldflags = [
    "-s"
    "-X main.version=${finalAttrs.version}"
  ];

  passthru.tests = {
    version = testers.testVersion { package = finalAttrs.finalPackage; };
    greets = runCommand "${finalAttrs.pname}-greets" {
      nativeBuildInputs = [ finalAttrs.finalPackage ];
    } ''
      [ "$(greet)" = "Hello, world!" ]
      [ "$(greet Nix)" = "Hello, Nix!" ]
      touch $out
    '';
  };

  meta = {
    description = "Greets you (Go implementation)";
    license = lib.licenses.mit;
    mainProgram = "greet";
  };
})
```

## Wire them up, with a contract test

```nix file=default.nix
let
  pkgs = import ./nixpkgs.nix {
    config = { };
    overlays = [ ];
  };
  inherit (pkgs) lib;

  greet-go = pkgs.callPackage ./greet-go.nix { };
  greet-rust = pkgs.callPackage ./greet-rust.nix { };
  greet-python = pkgs.callPackage ./greet-python.nix { };
in
{
  inherit greet-go greet-rust greet-python;

  # A flat set of every test, so `nix-build -A tests` builds them all.
  tests = {
    go-version = greet-go.tests.version;
    go-greets = greet-go.tests.greets;
    rust-version = greet-rust.tests.version;
    rust-greets = greet-rust.tests.greets;
    python-version = greet-python.tests.version;
    python-greets = greet-python.tests.greets;

    # The contract: all three print exactly the same thing.
    agree = pkgs.runCommand "greet-implementations-agree" { } ''
      run() { "$1"; "$1" Nix; "$1" --version; }
      run ${lib.getExe greet-go} > go.txt
      run ${lib.getExe greet-rust} > rust.txt
      run ${lib.getExe greet-python} > python.txt
      diff -u go.txt rust.txt
      diff -u go.txt python.txt
      cp go.txt $out
    '';
  };
}
```

## Build and run

The Go, Rust and Python toolchains come from the binary cache; only your code compiles.

```bash timeout=3600
nix-build -A greet-go -o result-go
nix-build -A greet-rust -o result-rust
nix-build -A greet-python -o result-python
for lang in go rust python; do
  printf '%-7s %s | %s | %s\n' "$lang" \
    "$(./result-$lang/bin/greet)" "$(./result-$lang/bin/greet Nix)" "$(./result-$lang/bin/greet --version)"
done
```

```text expect
go      Hello, world! | Hello, Nix! | greet 1.0.0
rust    Hello, world! | Hello, Nix! | greet 1.0.0
python  Hello, world! | Hello, Nix! | greet 1.0.0
```

## Verification

**Every test passes**, including the contract:

```bash timeout=1800
nix-build -A tests --no-out-link
cat "$(nix-build -A tests.agree --no-out-link)"
```

```text expect
Hello, world!
Hello, Nix!
greet 1.0.0
```

**The version test catches a lie.** Pretend to release 1.0.1 by overriding only the Nix
`version`. In Go the version is injected from Nix, so the binary follows and the test
passes. In Rust it comes from `Cargo.toml`, so the package now claims 1.0.1 and the binary
says 1.0.0 — exactly the mistake `testVersion` exists to catch:

```bash
nix-build --no-out-link -E '((import ./default.nix).greet-go.overrideAttrs { version = "1.0.1"; }).tests.version'
echo "go: version test passed"
```

```text expect
go: version test passed
```

```bash fails
nix-build --no-out-link -E '((import ./default.nix).greet-rust.overrideAttrs { version = "1.0.1"; }).tests.version'
```

```text expect
Version string '1.0.1' not found
```

Both overrides reach the tests because the tests use `finalAttrs.finalPackage`, the
package *after* `overrideAttrs`.

## Stretch goals

1. **One version, three sources.** Make `version` in Nix the single source of truth: in
   `postPatch`, `substituteInPlace` it into `Cargo.toml`, `Cargo.lock` and
   `pyproject.toml` (with `--replace-fail 'version = "1.0.0"' …`). Repeat the 1.0.1 override:
   now all three version tests pass. What is the downside of rewriting upstream's version?
2. **Fail early.** Add `versionCheckHook` to `nativeInstallCheckInputs` (with
   `doInstallCheck = true`) in each package, so a wrong version fails the *package* build,
   not only the separate test. Which is better for a slow test, and why?
3. **A dependency each.** Give each implementation one real dependency (a Go module, a
   crate, a PyPI package that exists in `python3Packages`) and use the fake-hash workflow for
   `vendorHash` / `cargoHash`. For Python, notice that there is no hash to get: the dependency
   comes from `python3Packages`.
4. **Generate the tests.** Replace the hand-written `tests` set with
   `lib.concatMapAttrs` over `{ go = greet-go; rust = greet-rust; python = greet-python; }`.

## Check yourself

<details><summary>Why does each package need its own copy of the two tests instead of one shared function?</summary>

It does not *need* to — a helper `mkGreetTests = pkg: { … }` works too. But the tests must
receive the package's `finalAttrs.finalPackage` from inside its own definition; that is what
makes `greet-rust.overrideAttrs …` test the overridden package. A shared helper called with
`finalAttrs.finalPackage` keeps that property.

</details>

<details><summary>The <code>agree</code> test passes. Does that prove the programs are correct?</summary>

No — it proves they agree on three inputs. Combined with the per-package `greets` tests
(which check the expected text), it covers the contract table above. Agreement tests shine
when you have a reference implementation and alternatives that must match it.

</details>

<details><summary>Where do the Python program's dependencies come from at runtime?</summary>

From the store paths baked into its wrapper and `#!` line: the Python interpreter and any
`dependencies` (here none). `buildPythonApplication` wraps console scripts so that the
right site-packages are on the module path, without `pip`, a virtualenv, or the network.

</details>

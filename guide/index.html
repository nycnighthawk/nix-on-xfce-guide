00The plan

You don't replace apt or pacman. Nix sits alongside them in /nix and only ever writes there. The aim is to split responsibilities so that nothing you install for development lands in the system.

apt / pacmanKernel, drivers, Xfce desktop, firmware, login manager, printing, and most GUI apps. Keep this layer small and boring.
Nix + Home ManagerYour user environment: CLI tools, shell config, git, Neovim with its plugins and language servers. One file, pinned by a lock file, the same on every machine.
Project flake + direnvCompilers, runtimes, per-project LSPs and the project's own Claude Code. They load when you cd into the project and disappear when you leave.
Tested 31 Oct 2026. Every step was run in User-Mode Linux VMs on Ubuntu 26.04 (Xubuntu's base), Linux Mint 22.3 "Zena" Xfce and current Arch, with Nix 2.35.4 and nixpkgs/Home Manager 26.05, using the code blocks extracted from this page. The Neovim config was also run natively: nil_ls/lua_ls attach, tree-sitter highlights, and format-on-save works.
Pick your distro at the top. Steps specific to that distro appear, and the progress bar tracks your checkboxes per distro (saved in this browser).

01Install Nix

This sets up a multi-user (daemon) install, the right choice on systemd distros: builds run as dedicated nixbld users, so the store stays clean.

Update the system and get prerequisites
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl xz-utils git
Linux Mint 22.x is built on Ubuntu 24.04, so every step here is the same as Xubuntu. Mint's update manager doesn't touch /nix.
Run the official installer in daemon mode

It's best to download and read the script before running it:

curl --proto '=https' --tlsv1.2 -sSfL https://nixos.org/nix/install -o nix-install.sh
less nix-install.sh          # read it
sh nix-install.sh --daemon

Answer y at the prompts. The installer creates /nix, the nixbld group and users, and a nix-daemon systemd unit. It also backs up and edits /etc/bash.bashrc.

Install Arch's native package

On Arch, use the repo package. pacman tracks it, and its systemd units and nixbld build users come pre-configured.

sudo pacman -Syu
sudo pacman -S --needed nix git
Enable the daemon and initialise the store
sudo systemctl enable --now nix-daemon.socket
sudo nix-store --init          # creates /nix/store; the package doesn't
systemctl status nix-daemon.socket --no-pager

Without nix-store --init, every command fails with error: opening file "/nix/store": No such file or directory, even with the daemon running.

Older guides tell you to join a nix-users group. Current Arch packages no longer create that group, and none is needed: the daemon socket is open to all users.
Log out of Xfce and back in

The package ships /etc/profile.d/nix-daemon.sh, which adds ~/.nix-profile/bin to PATH and Nix's share folders to XDG_DATA_DIRS at login. You don't need to edit ~/.bashrc.

Alternative: the upstream script (sh <(curl -L https://nixos.org/nix/install) --daemon) also works on Arch, but pacman won't know about it. Don't mix the two methods.
Open a new terminal and verify
nix --version
nix-shell -p hello --run hello     # should print "Hello, world!"

If nix isn't found, log out of Xfce and back in (or reboot) so the new profile scripts load.

nix --version
nix-instantiate --eval -E '1 + 1'  # prints 2: client, daemon and store all work

Skip nix-shell -p … here: it needs a channel, which the Arch package doesn't set up and this guide doesn't use. Step 02 downloads and runs a real package through flakes.

About the Determinate Systems installer: since early 2026 it installs only Determinate Nix, their downstream distribution, rather than upstream Nix. It's fine to use, but it enables flakes and manages nix.conf itself, so step 02 changes slightly. This guide uses upstream Nix.

02Enable flakes and sensible defaults

Flakes plus their flake.lock are what make an environment reproducible: every input is pinned to an exact commit.

Write /etc/nix/nix.conf settings
sudo tee -a /etc/nix/nix.conf >/dev/null <<'EOF'
experimental-features = nix-command flakes
max-jobs = auto
auto-optimise-store = true
trusted-users = root {{USER}}
EOF
Restart the daemon and check
sudo systemctl restart nix-daemon
nix config show | grep -E 'experimental-features|trusted-users'
nix run nixpkgs#cowsay -- "flakes work"

03Home Manager: your whole user environment in one repo

Home Manager installs your tools into ~/.nix-profile and generates your dotfiles from a single home.nix. Commit this folder to git and any machine reproduces it with one command.

Create the config repo
mkdir -p ~/.config/home-manager && cd ~/.config/home-manager
git init
Create flake.nix

This pins nixpkgs and Home Manager to the same stable release (26.05). Check status.nixos.org for the current release name.

~/.config/home-manager/flake.nix
{
  description = "{{USER}}'s home";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";
    home-manager = {
      url = "github:nix-community/home-manager/release-26.05";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };

  outputs = { nixpkgs, home-manager, ... }:
    let
      system = "{{SYS}}";
      pkgs = nixpkgs.legacyPackages.${system};
    in {
      homeConfigurations."{{USER}}" = home-manager.lib.homeManagerConfiguration {
        inherit pkgs;
        modules = [ ./home.nix ./nvim.nix ];
      };
    };
}
Create home.nix
~/.config/home-manager/home.nix
{ pkgs, ... }:
{
  home.username = "{{USER}}";
  home.homeDirectory = "/home/{{USER}}";
  home.stateVersion = "26.05";   # set once, never bump casually

  # Integrates with a non-NixOS distro: sets XDG_DATA_DIRS so Nix apps
  # show up in the Xfce Whisker menu, fixes locales and terminfo, etc.
  targets.genericLinux.enable = true;

  programs.home-manager.enable = true;

  home.packages = with pkgs; [
    ripgrep fd fzf jq bat eza tree htop
    gnumake unzip curl wget
  ];

  programs.bash = {
    enable = true;               # HM now owns ~/.bashrc (old one is backed up)
    shellAliases = { ll = "eza -la --git"; v = "nvim"; };
  };

  programs.git = {
    enable = true;
    settings.user.name  = "Your Name";        # older HM: userName
    settings.user.email = "you@example.com";  # older HM: userEmail
  };

  # direnv + nix-direnv: auto-load project shells (section 05)
  programs.direnv = {
    enable = true;
    nix-direnv.enable = true;
  };

  home.sessionVariables = {
    EDITOR = "nvim";
    PIP_REQUIRE_VIRTUALENV = "true";   # refuse global pip installs
  };
}
Create a placeholder nvim.nix (filled in at step 04)
echo '{ ... }: { }' > ~/.config/home-manager/nvim.nix
Bootstrap and switch

Flakes only see files that git tracks, so git add them first. That's the #1 "file not found" gotcha.

cd ~/.config/home-manager
git add -A
nix run home-manager/release-26.05 -- switch -b backup --flake .#{{USER}}
# after the first run the command exists in your profile:
home-manager switch --flake ~/.config/home-manager#{{USER}}

-b backup renames any dotfile that's in the way to *.backup instead of failing. Commit flake.lock, since it is the pin.

cd ~/.config/home-manager && git add -A && git commit -m "initial home"
Log out of Xfce and back in

Session variables (XDG_DATA_DIRS, EDITOR) only reach the desktop and Whisker menu after a fresh login.

GUI apps from Nix need your GPU drivers. targets.genericLinux.enable also turns on Home Manager's GPU integration, and the first switch prints a one-time command (sudo /nix/store/…-non-nixos-gpu/bin/non-nixos-gpu-setup). Run it once. With the proprietary NVIDIA driver, also set targets.genericLinux.gpu.nvidia = { enable = true; version = "…"; }; to the exact version the host uses. The simplest setup is still browsers and other GUI apps from apt or Flatpakpacman or Flatpak, with Nix for CLI and dev tools.

04Neovim, declaratively

Neovim, every plugin, every tree-sitter grammar and the always-on language servers all come from the pinned nixpkgs. Nothing gets downloaded at startup, and a fresh machine gets an identical editor.

Replace nvim.nix
~/.config/home-manager/nvim.nix
{ pkgs, ... }:
{
  programs.neovim = {
    enable = true;
    defaultEditor = true;
    viAlias = true;
    vimAlias = true;

    # Tools on nvim's PATH only. Global, project-agnostic LSPs go here;
    # language-specific ones belong in each project's flake (section 05).
    extraPackages = with pkgs; [
      lua-language-server
      nil                      # Nix LSP
      nixfmt
      stylua
      ripgrep fd               # for telescope
      tree-sitter
    ];

    plugins = with pkgs.vimPlugins; [
      nvim-treesitter.withAllGrammars
      nvim-lspconfig
      telescope-nvim plenary-nvim telescope-fzf-native-nvim
      blink-cmp
      conform-nvim
      gitsigns-nvim
      lualine-nvim nvim-web-devicons
      which-key-nvim
      tokyonight-nvim
    ];

    # initLua was called extraLuaConfig before Home Manager 26.05
    initLua = ''
      vim.g.mapleader = " "
      vim.o.number = true
      vim.o.relativenumber = true
      vim.o.expandtab = true
      vim.o.shiftwidth = 2
      vim.o.termguicolors = true
      vim.o.signcolumn = "yes"
      vim.cmd.colorscheme("tokyonight-night")

      -- nvim-treesitter (main branch, as in nixpkgs 26.05) only ships parsers +
      -- queries; highlighting is Neovim's own. Start it for every filetype that has one.
      vim.api.nvim_create_autocmd("FileType", {
        callback = function(ev)
          if pcall(vim.treesitter.start, ev.buf) then
            vim.bo[ev.buf].indentexpr = "v:lua.require'nvim-treesitter'.indentexpr()"
          end
        end,
      })
      require("lualine").setup({})
      require("gitsigns").setup({})
      require("which-key").setup({})
      require("blink.cmp").setup({ keymap = { preset = "default" } })

      local tb = require("telescope.builtin")
      require("telescope").load_extension("fzf")
      vim.keymap.set("n", "<leader>ff", tb.find_files, { desc = "Find files" })
      vim.keymap.set("n", "<leader>fg", tb.live_grep,  { desc = "Grep" })
      vim.keymap.set("n", "<leader>fb", tb.buffers,    { desc = "Buffers" })

      -- Neovim 0.11+ native LSP API; nvim-lspconfig supplies server defaults.
      -- Servers that aren't on PATH are skipped, so project shells can add
      -- pyright, rust-analyzer, gopls, ts_ls, ... and they just start.
      vim.lsp.config("*", { capabilities = require("blink.cmp").get_lsp_capabilities() })
      vim.lsp.enable({ "lua_ls", "nil_ls", "pyright", "ruff",
                       "rust_analyzer", "gopls", "ts_ls", "clangd" })

      require("conform").setup({
        formatters_by_ft = { nix = { "nixfmt" }, lua = { "stylua" },
                             python = { "ruff_format" }, rust = { "rustfmt" } },
        format_on_save = { timeout_ms = 1000, lsp_format = "fallback" },
      })
    '';
  };
}
Version your existing config through Home Manager

Move your current config into the repo. Home Manager links it into place, and Nix still provides Neovim and the LSPs. Commit lazy-lock.json so plugin versions are pinned too.

mv ~/.config/nvim ~/.config/home-manager/nvim
cd ~/.config/home-manager && git add nvim
~/.config/home-manager/nvim.nix
{ pkgs, config, ... }:
{
  programs.neovim = {
    enable = true;
    defaultEditor = true;
    sideloadInitLua = true;   # HM won't write ~/.config/nvim/init.lua; yours lives there
    extraPackages = with pkgs; [
      lua-language-server nil nixfmt stylua
      ripgrep fd tree-sitter gcc gnumake   # gcc: for treesitter parsers
    ];
  };

  # Out-of-store link so lazy.nvim can still update lazy-lock.json in place
  xdg.configFile."nvim".source =
    config.lib.file.mkOutOfStoreSymlink
      "${config.home.homeDirectory}/.config/home-manager/nvim";
}
Turn off Mason, or at least don't use it to install language servers. Its binaries are generic Linux builds that often break with Nix, and they bypass your lock file. Let Nix supply the servers instead.
Apply and check
cd ~/.config/home-manager && git add -A
home-manager switch --flake .#{{USER}}
nvim +checkhealth

05Per-project dev shells

Each project gets its own flake.nix listing its toolchain. When you cd in, direnv loads it, and Neovim started from that shell sees the project's compiler and LSP. Teammates and CI get the exact same versions from flake.lock.

Pick a template and save it as flake.nix in the project root

06Develop with Claude Code: isolated projects, reproducible builds

Claude Code runs commands for you, and a coding agent installs things freely. Without guard rails, project A's npm install -g or pip install changes what project B sees, and "works on my machine" becomes "works in my session". This section gives every project its own pinned toolchain, its own caches and its own Claude Code version, and makes a sandboxed nix build the definition of done.

What leaks between projectsWhat stops it here
Different compiler/runtime versionsEach project's flake.nix + flake.lock pins its toolchain
Shared caches and "global" installs (~/.npm, ~/.cache/pip, ~/.cargo, ~/go)The dev shell points every tool's cache and global prefix into the project's .cache/
The agent changing your system, or reading another projectClaude Code's sandbox (bubblewrap) and permission rules in .claude/settings.json
Claude Code itself updating under youClaude Code comes from the project's nixpkgs pin; Nix's build turns off its self-updater
"It builds in my shell"nix build and nix flake check: hermetic, and enforced by a Stop hook
Let Nix's bubblewrap create sandboxes

Claude Code's sandbox uses bubblewrap. The copy Nix provides lives in /nix/store, but Ubuntu's AppArmor only lets /usr/bin/bwrap create the user namespaces a sandbox needs. Grant the same permission to Nix's bubblewrap, and nothing more:

sysctl kernel.apparmor_restrict_unprivileged_userns 2>/dev/null || true   # 1 = restricted
nix run nixpkgs#bubblewrap -- --unshare-all --ro-bind / / --dev /dev true || echo "blocked by AppArmor (expected before the fix)"
sudo tee /etc/apparmor.d/nix-bwrap > /dev/null <<'EOF'
# Let bubblewrap from the Nix store create user namespaces, as Ubuntu allows for /usr/bin/bwrap
abi <abi/4.0>,
include <tunables/global>

profile nix-bwrap /nix/store/*-bubblewrap-*/bin/bwrap flags=(unconfined) {
  userns,
  include if exists <local/nix-bwrap>
}
EOF
sudo apparmor_parser -r /etc/apparmor.d/nix-bwrap
nix run nixpkgs#bubblewrap -- --unshare-all --ro-bind / / --dev /dev true && echo "bubblewrap sandbox works" 
# Arch doesn't restrict user namespaces; just check
nix run nixpkgs#bubblewrap -- --unshare-all --ro-bind / / --dev /dev true && echo "bubblewrap sandbox works"
Create project A

A tiny Node app stands in for real code. What matters is the shape: a git repository, the app, and a .gitignore that keeps per-project caches and build links out of git.

mkdir -p ~/code/project-a && cd ~/code/project-a && git init -q
cat > app.js <<'EOF'
const name = require("path").basename(__dirname); // $out/share/<project>
console.log(`${name} running on Node ${process.version}`);
EOF
printf '.cache/\n.direnv/\nresult\n' > .gitignore
Write project A's flake.nix

One file declares the reproducible build (packages), the place you and Claude Code work (devShells, which includes Claude Code itself) and what must pass (checks).

~/code/project-a/flake.nix
{
  description = "project-a";
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";

  outputs = { self, nixpkgs }:
    let
      system = "x86_64-linux";
      pkgs = import nixpkgs {
        inherit system;
        # Claude Code is unfree: allow exactly that one package
        config.allowUnfreePredicate = pkg: builtins.elem (nixpkgs.lib.getName pkg) [ "claude-code" ];
      };
      name = "project-a";
      nodejs = pkgs.nodejs_22; # project B: nodejs_24
      python = pkgs.python312; # project B: python313
    in
    {
      # The reproducible build: sandboxed, from git-tracked files and the locked nixpkgs only.
      packages.${system}.default = pkgs.stdenvNoCC.mkDerivation {
        pname = name;
        version = "0.1.0";
        src = ./.;
        __structuredAttrs = true;
        nativeBuildInputs = [ pkgs.makeWrapper ];
        installPhase = ''
          runHook preInstall
          install -Dm644 app.js $out/share/${name}/app.js
          makeWrapper ${nodejs}/bin/node $out/bin/${name} --add-flags $out/share/${name}/app.js
          runHook postInstall
        '';
      };

      # Where you and Claude Code work: this project's tools, pinned, plus Claude Code itself.
      devShells.${system}.default = pkgs.mkShell {
        # bubblewrap + socat: what Claude Code's sandbox runs on Linux
        packages = [ nodejs python pkgs.claude-code pkgs.bubblewrap pkgs.socat pkgs.git pkgs.jq ];
        shellHook = ''
          root=$(git rev-parse --show-toplevel 2>/dev/null || pwd)
          # Every language tool keeps its caches and "global" installs inside this project.
          export npm_config_cache="$root/.cache/npm"
          export npm_config_prefix="$root/.cache/npm-global"
          export PIP_CACHE_DIR="$root/.cache/pip"
          export UV_CACHE_DIR="$root/.cache/uv"
          export PIP_REQUIRE_VIRTUALENV=true
          export GOPATH="$root/.cache/go" GOMODCACHE="$root/.cache/go/mod"
          export CARGO_HOME="$root/.cache/cargo"
          export PATH="$npm_config_prefix/bin:$PATH"
        '';
      };

      checks.${system}.build = self.packages.${system}.default;
    };
}
Make project B with different versions

Project B is the same project on newer runtimes: Node 24 and Python 3.13. Both can be open at once.

mkdir -p ~/code/project-b && cd ~/code/project-b && git init -q
cp ~/code/project-a/{app.js,.gitignore,flake.nix} .
sed -i -e 's/project-a/project-b/g' -e 's/nodejs_22;/nodejs_24;/' -e 's/python312;/python313;/' flake.nix
git add -A
cd ~/code/project-a && git add -A
Prove the projects don't interfere

Each project gets its own versions. A "global" npm install inside project A lands in A's .cache/, so project B and the rest of your system never see it:

cd ~/code/project-a && nix develop -c bash -c 'node --version; python --version; npm install -g --silent cowsay; cowsay "installed in A"'
cd ~/code/project-b && nix develop -c bash -c 'node --version; python --version; command -v cowsay || echo "project B: no cowsay"'
command -v cowsay || echo "rest of the system: no cowsay"
ls ~/code/project-a/.cache/npm-global/bin
Pin Claude Code per project

Claude Code comes from each project's locked nixpkgs. It's never installed globally, and the Nix build disables its self-updater, so it changes only when you run nix flake update in that project. Each project could even pin a different version.

cd ~/code/project-a && nix develop -c claude --version
cd ~/code/project-b && nix develop -c claude --version
command -v claude || echo "not installed globally"
Give Claude Code each project's rules

.claude/settings.json is committed with the project, so every session follows it:

  • Permissions: allow the Nix build commands; ask before updating the lock or pushing; deny global installs and secrets.
  • Sandbox: Claude's commands run in bubblewrap. They can write only inside the project, can't read the other project or your keys, and reach only the listed hosts. allowUnixSockets lets Nix commands reach the Nix daemon.
  • Stop hook: before Claude says it's done, nix flake check must pass. If it fails, the last lines go back to Claude (exit code 2) and it keeps working.

CLAUDE.md tells Claude the same rules in words. Both files go into project B too, with the sandbox pointed at project A instead:

cd ~/code/project-a
mkdir -p .claude
cat > .claude/settings.json <<'EOF'
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      "Bash(nix build *)",
      "Bash(nix flake check *)",
      "Bash(nix develop *)",
      "Bash(git status)",
      "Bash(git diff *)"
    ],
    "ask": ["Bash(nix flake update *)", "Bash(git push *)"],
    "deny": [
      "Bash(sudo *)",
      "Bash(nix profile *)",
      "Bash(nix-env *)",
      "Bash(npm install -g *)",
      "Bash(pip install --user *)",
      "Read(./.env)",
      "Read(~/.ssh/**)"
    ]
  },
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false,
    "filesystem": {
      "denyRead": ["~/code/project-b", "~/.ssh", "~/.aws", "~/.gnupg"]
    },
    "network": {
      "allowedDomains": [
        "cache.nixos.org", "channels.nixos.org", "github.com", "codeload.github.com",
        "registry.npmjs.org", "pypi.org", "files.pythonhosted.org"
      ],
      "allowUnixSockets": ["/nix/var/nix/daemon-socket/socket"]
    }
  },
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "out=$(nix flake check 2>&1) || { echo \"$out\" | tail -n 20 >&2; exit 2; }",
            "timeout": 900
          }
        ]
      }
    ]
  }
}
EOF
cat > CLAUDE.md <<'EOF'
# project-a: rules for Claude Code

The toolchain comes from `flake.nix` (Node 22, Python 3.12) and is pinned by `flake.lock`.

- Work inside the dev shell. If a tool is missing, add it to `devShells.default.packages` in
  `flake.nix`. Never install anything globally (`sudo apt`, `nix profile`, `npm -g`, `pip --user`).
- Caches and installs live in `.cache/` (set by the dev shell). Don't change those variables.
- Python: use a virtualenv in `.venv`; plain `pip install` is refused on purpose.

The reproducible build

The dev shell is for working; nix build is the truth. It builds in Nix's sandbox from git-tracked files and the locked nixpkgs only, so it gives the same result on any machine. --rebuild builds again and compares bit for bit. Commit flake.lock with the code; it is the version of everything.

cd ~/code/project-a
nix build
./result/bin/project-a
nix build --rebuild && echo "rebuilt bit-for-bit identical"
nix flake check
# Claude's Stop hook runs exactly this; it passes now
sh -c "$(jq -r '.hooks.Stop[0].hooks[0].command' .claude/settings.json)" && echo "Stop hook passes"
git commit -qm "project-a: initial" && git log --oneline | head -1
cd ~/code/project-b && nix build && ./result/bin/project-b && git commit -qm "project-b: initial"
Update one project, never both

Each lock moves only when you update that project, so upgrading B's toolchain (or its Claude Code) can't break A:

for p in project-a project-b; do
  (cd ~/code/$p && echo "$p: nixpkgs $(nix flake metadata --json | jq -r .locks.nodes.nixpkgs.locked.rev | cut -c1-12)")
done
cd ~/code/project-b && nix flake update && nix flake check && git commit -qam "project-b: update inputs" || echo "already up to date"
Running several Claude Code sessions on the same project at once? Give each its own git worktree (git worktree add ../project-a-feature). Each worktree is a separate directory with the same flake, so sessions don't overwrite each other's files.

Once Nix provides them, remove the distro copies, for example:

Never remove the distro's own python3 (Ubuntu/Mint system tools depend on it) or base-devel (Arch needs it for the AUR). Leave those alone. Your PATH puts ~/.nix-profile/bin first, so the Nix versions win.

08Update, roll back, clean up

Update your home environment deliberately
cd ~/.config/home-manager
nix flake update                         # bumps flake.lock
home-manager switch --flake .#{{USER}}
git commit -qam "bump inputs" || echo "already up to date"   # undo: git checkout flake.lock
Roll back if an update breaks something
home-manager generations                 # list, newest first
# copy the store path of the generation you want, then:
/nix/store/<hash>-home-manager-generation/activate
Reclaim disk space
home-manager expire-generations "-30 days"
nix-collect-garbage --delete-older-than 30d
sudo nix-collect-garbage --delete-older-than 30d
du -sh /nix/store

To automate it, add to home.nix: nix.gc = { automatic = true; dates = "weekly"; options = "--delete-older-than 30d"; };
